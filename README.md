# Personal AI Dashboard

**Developed by Dor Meir**, using Claude Code as an AI-assisted engineering team (Architect, Coder and independent Verifier agents in `.claude/agents/`) under the author's direction, review and approval. Planning, product decisions and approvals were the author's; much of the code was generated by the agents and independently verified before integration.

A private, local dashboard for your own records (food and health, content you consume, job
applications and tasks) with **agentic data analytics** over them. It shows deterministic
history, aggregates and charts, and an **Analyst** that answers natural-language questions about
your records. The model chooses read-only tools; the backend computes every number and checks the
answer against the evidence before it is shown. When the records cannot support an answer, the
app says so instead of guessing.

A **Demo Mode** with an entirely synthetic 30-day dataset runs with no Google account and no
OpenAI key.

Then open http://localhost:8000 and choose **Explore demo data**.

**AI validation status.** The Analyst's tools, Evidence Validation, repair-then-degrade logic,
user isolation and demo isolation are tested end to end with a *scripted* model that drives the
real backend. No live OpenAI call has been made, and the offline golden question set has not been
run, so real-model answer quality, latency and cost are not measured (report §6.3). With your own
key the Analyst runs on the synthetic data; without one it shows a fixed "not available" message.

## Architecture
```
Browser ──HTML forms / HTMX──▶ FastAPI (server-rendered Jinja templates, no JS build step)
                                 ├─ auth: Google OIDC (personal) or local demo identity (demo)
                                 ├─ records: validated repositories, parameterized SQL, user-scoped
                                 ├─ aggregates: metric registry → summaries, comparison, SVG charts
                                 ├─ analytics: six read-only tools → evidence ledger
                                 │              → OpenAI (function calling)
                                 │              → deterministic Evidence Validation → rendered answer
                                 └─ SQLite (STRICT tables, foreign keys, guard triggers, migrations)
```
| Layer | Where |
|---|---|
| Web, forms, aggregates and Analyst pages | `app/main.py`, `app/web/` |
| Sign-in, session, CSRF | `app/auth.py` |
| Records and data preservation | `app/records/`, `app/deletion.py`, `migrations/` |
| Metrics, tools, ledger, validator, agent | `app/analytics/` |
| OpenAI client (injected, replaceable in tests) | `app/ai_client.py` |
| Demo Mode | `app/demo.py`, `demo/`, `scripts/build_demo_fixture.py` |
| Configuration (validated at startup) | `app/config.py`, `.env.example` |

- The model never writes SQL and never writes numbers: it chooses tools and writes text with
  placeholders such as `{{E2.mean}}`; the backend fills every value from tool results.
- Tools run on a read-only connection, always scoped to the signed-in user.
- Design records: `docs/architecture/ADR-004-data-preservation.md`,
  `docs/architecture/ADR-005-personal-ai-analytics.md`. Product behavior: `PRODUCT_SPEC.md`.
  Technical report (design decisions, development method, verification evidence, limitations):
  [`docs/submission/report/Personal-AI-Dashboard-Technical-Report.pdf`](docs/submission/report/Personal-AI-Dashboard-Technical-Report.pdf).

## Demo Mode (no Google account, no OpenAI key, no `.env`)
Windows PowerShell:
```powershell
scripts\start.ps1 -Demo      # http://localhost:8000; never opens a tunnel
scripts\stop.ps1             # stop it
```
Without the scripts:
```powershell
$env:APP_MODE="demo"; .venv\Scripts\python.exe -m uvicorn app.main:create_app --factory --host 127.0.0.1 --port 8000
```
```bash
APP_MODE=demo .venv/bin/python -m uvicorn app.main:create_app --factory --host 127.0.0.1 --port 8000
```
Open http://localhost:8000 and choose **Explore demo data**. `scripts\start.ps1` also accepts
`-Port <n>` (default 8000).

The dataset: about 30 days of invented records for one fictional person (meals, workouts, sleep,
steps, weight, content, job applications with interviews, and tasks such as family, friends,
chores and dog care). It is generated by `scripts/build_demo_fixture.py` (seeded and reproducible;
`--check` verifies the committed files) and is a **draft pending the owner's approval**.

How it works:
- Every start builds a fresh working copy (`data/demo/working-<n>.db`, gitignored) from the
  committed fixture `demo/synthetic_v1.json`. The fixture must match `demo/synthetic_v1.sha256`
  or the app refuses to start. Dates are stored as day offsets and shifted so the data ends today.
- Your changes stay in the working copy. **Reset demo data** (in the demo banner, with a
  confirmation page) rebuilds it, as does a restart. With the server stopped:
  `.venv\Scripts\python.exe scripts\demo_reset.py` (or `.venv/bin/python scripts/demo_reset.py`).
- Local-only: it refuses an https or tunnel `PUBLIC_BASE_URL` and `TEST_AUTH=1`, ignores the
  Google settings, and answers 403 to any request not made directly on this computer.
- It never opens a personal database, and personal mode never opens a demo database. The Analyst
  reads only the demo working copy.
- `SESSION_SECRET` may be left unset; a random one is generated per run.

## The dashboard
After sign-in (or **Explore demo data**) there are four data tabs (Food & Health, Content,
Jobs & Career, Tasks) and the **Analyst** tab. Each data tab has two views:
- **History**: up to 15 days per domain, add/edit forms, delete with confirmation, and a
  **Recently deleted** page (restore or delete permanently). A day without a record shows
  "No record entered for this day" and is never treated as zero.
- **Aggregates**: ranges of the last 7, 14 or 30 days, or custom From/To dates (up to 366 days,
  ending today at the latest). Metric tiles show averages over recorded days, totals and coverage.
  A comparison table sets the selected range against the previous period of equal length;
  changes below a metric's threshold read "no clear change", and fewer than 3 recorded days in
  either period reads "not enough data". Server-rendered SVG charts leave **visible gaps** on
  undocumented days, and each chart has a "Show data" table.

## The Analyst
### Without an OpenAI key
Everything except the Analyst works. In Demo Mode the Analyst shows, verbatim:

> AI-powered analysis is not available in the current demo configuration. You can still explore
> the sample data, metrics, and trends. To enable the analytical agent, configure your own OpenAI
> API key using the setup instructions.

In personal mode it shows: "AI-powered analysis is not configured. Add OPENAI_API_KEY and
OPENAI_MODEL to .env (see README) to enable it." No AI answer is ever simulated.

### With your own key
1. Create an API key in your OpenAI account and set a **monthly budget limit** there first.
2. Copy `.env.example` to `.env` (gitignored; never commit it) and set:
   ```
   AI_ENABLED=1
   OPENAI_API_KEY=<your key>
   OPENAI_MODEL=<a model that supports function calling and structured outputs>
   AI_MAX_TOKENS_PER_QUESTION=40000
   AI_QUESTIONS_PER_HOUR=20
   ```
   AI runs only when `AI_ENABLED=1` and both the key and the model are set. The last two values
   are the defaults: a per-question token budget and a per-user hourly question cap. To set the key
   for the current PowerShell window only:
   ```powershell
   $env:OPENAI_API_KEY="<your key>"; $env:OPENAI_MODEL="<model>"; scripts\start.ps1 -Demo
   ```
3. Revoke the key in your OpenAI account when you no longer need it.

How an answer is produced:
- One OpenAI function-calling agent with six **read-only** tools: `get_data_coverage`,
  `summarize_metric`, `compare_periods`, `get_daily_series`, `relate_metrics`, `list_records`.
- Each question is bounded: at most 500 characters, 8 tool calls and 6 model turns, plus the
  token budget and hourly cap above.
- The **backend computes every number**. Tool results go into an evidence ledger, and the model's
  answer may only reference them through placeholders.
- **Evidence Validation** is deterministic (rules V1–V14): schema, cited evidence, numbers and
  number words, causal or predictive language, URLs and markup, status consistency and chart
  sources. Invalid parts are dropped; if nothing valid remains, the insufficient-evidence message
  is shown.
- **Evidence** under each answer lists every calculation that was run, with its period and
  coverage.

Example questions over the demo data (patterns built into the fixture):
| Question | Intended kind of answer |
|---|---|
| "How did my sleep in the first half of the month compare with the second half?" | A comparison with coverage for both periods |
| "Did my friend meetings change during the month?" | Meetings recorded in weeks 1–2, none in weeks 3–4 |
| "Are my steps higher on workout days?" | An association with an "association only, not cause" caveat |
| "How has my weight changed over the last week?" | Partial or insufficient: too few measurements |
| "How did my mood change this month?" | The insufficient-evidence message: mood is not tracked |

## Personal mode (optional, Google sign-in)
1. In Google Cloud Console create an OAuth client of type **Web application** with the redirect
   URI `http://localhost:8000/auth/callback`.
2. Copy `.env.example` to `.env` and set `SESSION_SECRET` (generate with
   `python -c "import secrets; print(secrets.token_hex(32))"`), `GOOGLE_CLIENT_ID`,
   `GOOGLE_CLIENT_SECRET` and `ALLOWED_EMAILS` (your account only). `DATABASE_PATH` defaults to
   `data/app.db` (gitignored).
3. Run `scripts\start.ps1 -NoTunnel` (or the uvicorn command above without `APP_MODE=demo`),
   open http://localhost:8000 and choose **Sign in with Google**.

The app validates configuration at startup and names a missing or invalid setting without
printing its value; placeholder secrets are rejected. The first sign-in binds the allowlisted,
Google-verified email to the account's stable Google ID. Sessions are signed cookies valid for
8 hours, and every request that changes data carries a CSRF token.

Temporary phone access (personal mode only): `scripts\start.ps1` without `-NoTunnel` opens a
Cloudflare quick tunnel. Its URL changes on every start, so the Google redirect URI must be
updated each time. Stop the app and tunnel with `scripts\stop.ps1`.

To start a personal database empty, stop the server and move or delete `DATABASE_PATH` yourself;
the schema is recreated on the next start. In the app, records are soft-deleted first and can be
restored from **Recently deleted**.

## Tests and checks
```powershell
scripts\check.ps1      # ruff check app tests scripts, mypy (strict), pytest
```
```bash
.venv/bin/ruff check app tests scripts && .venv/bin/mypy && .venv/bin/pytest
```
Automated tests never call OpenAI or Google: the OpenAI client is injected and replaced by
scripted models, and Google is simulated. Layers: unit; database integration (constraints,
migrations, multi-process concurrency, data preservation); security (session, CSRF, test-login
loopback, SSRF, mode isolation); web forms; Demo Mode and fixture integrity; aggregates; analytics
tools, validator and scripted-model agent tests.

## Security and data integrity
- The backend owns the database, OpenAI calls, sign-in, validation and secrets; the browser never
  sees a key.
- Every query is parameterized and filtered by the signed-in user's id, taken from the session,
  never from the request.
- Database uniqueness per user and business key is authoritative: duplicates are rejected with a
  clear message, there is no `REPLACE`/`UPSERT` and no cascading delete, and records change only
  through manual, authenticated edit and delete (soft delete first, permanent delete only after
  confirmation).
- Model output is untrusted data: it cannot run SQL, write records, reach the network or insert
  numbers, URLs or markup into an answer.
- Demo Mode is isolated: the Analyst reads only the demo working copy, and the personal database
  stays unchanged, including after a reset.
- `.env`, databases, logs, screenshots, documents and media are gitignored. Use only synthetic
  data for demos, and stop the tunnel and revoke the OpenAI key afterwards.

## Known limitations
- Single-user local application, not a production deployment; it is offline when the process
  stops.
- Evidence Validation's lexical rules are English-only and best-effort.
- Thresholds are heuristics, not statistical significance tests.
- Questions are single-turn.
- Rate limits are per process.
- `relate_metrics` has no filters, so it splits steps by any workout, not by aerobic workouts
  only.
- A comparison in which one period has zero events falls back.
- The synthetic dataset is a draft pending owner approval.
- Sign-out doesn't revoke a copied session cookie before its 8-hour expiry.
- Demo dates shift to end today; a working copy built before midnight is one day behind after
  midnight until reset.
